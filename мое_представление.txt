
VisioBible отличная программа для вывода цитат из библии и песен на экран. 
но у нее отсутствует возможность удобной синхронизации мест из библии и песен между программами. 
она хранит песни и цитаты в vbm модулях, которые можно переносить между программами. 
Но это не безопасно, если в двух версиях модуля добавились разные песни. 
при переносах некоторые песни из обновленных модулей могут затереться и исчезнуть
Мое решение:
Сделать программу синхронизации через сервер. 
структура модуля:
`.vbm` — бинарный файл: **заголовок + сжатое zlib содержимое + завершающее поле**. Внутри структура такая:

```
Песенник
├─ Название и короткое название
├─ Издатель, дата ревизии, комментарий
├─ Песни[]
│  ├─ Название и альтернативное название
│  ├─ Автор текста и композитор
│  ├─ Примечание
│  ├─ Свойства (текстовые строки $KEY$=значение)
│  └─ Части[]
│     ├─ Тип: Куплет, Припев, Мост…
│     ├─ Текст
│     └─ Выравнивание
└─ Группы[]
   ├─ Название
   └─ Индексы песен в списке
```

**Заголовок файла:** сигнатура `VisioBibleModule`, версия формата, размеры сжатых и распакованных данных,
 флаги, поле кодировки, резервные байты и короткое/полное название песенника.
Числа записаны в порядке little-endian. В проверенных файлах строки — длина `u16`, 
затем текст UTF-16LE. Перед списками песен, частей и групп записано количество элементов `u32`.

Например, свойства первой песни песенника после теста:

```
$TUNE$=До маж
$ID$=1 
```

ID не уникальный. отображает только номер строки. но можно добавить свои данные. 
например, $FBID$=fba56871-f5d6-4b32-8b42-4bca03278ec1. после изменения песенника и песен, id сохраняется. 
присвоить каждой песне свой хеш. + делать дерево хешей MinHash для куплетов и остальных частей.
В VisioBible есть встроенный список модулей. можно помечать их как публичные.

Взаимодействие:
синхронизатор составляет две части: клиентская программа и сервер с сайтом, панелью админа и апи.

пользователь может зарегистрироваться на сайте, зарегистрировать свою общину, или присоединиться 
к ней по сгенерированной ссылке приглашению.
потом может авторизироваться в программе и программа просканирует пк на поиск папки с VisioBible
если не найдет, попросит указать вручную. если найдет несколько, то тоже попросит выбрать нужную.
потом сохранит свои настройки в AppData/flammebible
+ пользователь должен указать Dimensions из списка доступных. по умолчанию выбирается личный. 
после этого найдет конфиг библии VisioBible.ini, в котором перечислены модули. если его нет, то 
ищет папку modules рядом с бинарником VisioBible
читает список модулей, индексирует их. переводы библии предоставлены ввиде директорий 
с html файлами и bibleqt.ini (Modules/bti'15 » ls

)

а песни содержатся ввиде vbm модулей.
с переводами библий проще. вероятность что версии одного перевода разнятся у пользователей мала. но 
бывают ошибки перевода, которые надо исправлять. по этому программа считает хеши книг, общий хеш и прописывает 
это в bibleqt.ini. + назначает каждому переводу кастомный uuid. если перевод уже есть на сервере и хеши совпадают,
то просто прописывается в bibleqt.ini uuid и в Dimensions добавляются id перевода. если еще перевода нет на сервере,
то все книги перевода индексируется и загружается на сервер как приватный перевод, с возможностью запроса публикации.
после модерации он может быть опубликован.
если же у юзера частично совпадают книги, но в некоторых ошибки, которые надо исправить, он может послать запрос на изменение
(или он пошлется автоматически при первой индексации)
(todo добавить модель запросов + флаг для перевода библии)
в песнях планирую использовать систему патчей. есть исходные модули песен, поставляемые visioBible.
при добавлении новых песен, они пишутся не в ISongbook.song сборника, а создается 
новый сборник IContainerSongBox с указанием на родительский. а у клиента оно сливается в один сборник. 
и отображается в веб приложении тоже как один сборник, но с отдельным разделом "добавленные песни"
если у оригинального сборника добавились новые песни, они автоматически отображаются у юзера, из за ссылки 
на родительский сборник.
если в родительский сборник добавилась идентичная песня, которую юзер добавлял вручную, то песня юзера удаляется,
а родительская остается и отображается в разделе родительских песен.

из за чего номер песни меняется.а массово менять номера в бд для всех песен в родительском сборнике и возможных патчах 
это слишком дорого. возможно сделать какую то модель индекса песен для IContainerSongBox. и какой то механизм 
автоматического расчета индекса для fbid
сначала выстроить индекс родителя, а потом поверх него наложить индекс патча.

синхронизация:
иногда у песен могут быть разные вариации, отличающиеся только одним словом в припеве. тогда было бы не целесообразно
хранить дубликаты копий песен. по этому для каждого куплета тоже высчитываем хеш. для экономии места в бд и уменьшения запросов,
можно использовать хеш как ObjectId.

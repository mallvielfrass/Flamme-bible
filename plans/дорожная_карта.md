# Дорожная карта

Контракт описан в `архитектура.md`. Задачи и порядок работы — в `таски.md`. Календарных сроков нет. Оригиналы модулей и программа VisioBible не изменяются ради разработки. Рабочие пробы идут на копиях.

## Уже есть

Разбор и запись VBM, round-trip одного файла, один GUI-тест `$FBID$` в VisioBible 2.3 под Wine, узкая проверка `BibleId` и `BookHash` в `rst+` на VisioBible 2.5.0.1332, образец `plan.vplt` и факт, что сохранение плана стирает незнакомые теги.

Не проверено и поэтому закрыто отказом, а не догадкой: группы, смысл `align`, повторное открытие FBID-файла, копирование песни с тем же `$FBID$`, запись при открытой VisioBible, жизненный цикл VBI, `BookHash` на остальных книгах, сохранение `IDLog`.

## Срез 1. Песни

Регистрация, личное пространство, одна община по приглашению, одна книга. Ручной sync двух пользователей при закрытой VisioBible. API и минимальные экраны Vue: вход, пространство, приглашение, состояние. Клиент — CLI на Go.

Приёмка:

- A добавил песню X, B добавил Y. После любого порядка sync обе есть у обоих.
- Разные песни сходятся без конфликта.
- Одна и та же песня, изменённая двумя, остаётся конфликтом последнего слияния. Оба текста доступны, пока человек не выберет серверную версию с последующей своей правкой или новую песню.
- Удаление против правки не исчезает молча.
- Повтор push не создаёт вторую песню.
- Обрыв между страницами pull не перескакивает неприменённые события.
- Часы клиентов не выбирают победителя.
- Открытая VisioBible блокирует замену VBM.
- Чужое пространство недоступно по угаданному id.
- Конкурентная запись не пропускает seq.
- Файл с группами не перезаписывается.
- Отсутствие файла не превращается в удаление всей книги.
- Сбой проверки возвращает резервную копию VBM и VBI.

## Срез 2. Каталог

Публичный сборник, запрос публикации, модерация. Совпадение по хешу и MinHash показывается человеку. Автоудаления копии патча нет.

## Срез 3. Тексты, планы, Библия

Синхронизация `plan.vplt` через соседний `имя.vplt.sync` по правилу из архитектуры. Затем индексирование BibleQuote и запросы правки перевода. `BibleId` в шапку модуля пишется только по проверенному для этой сборки способу. `BookHash` на все книги — после такой же проверки, как у Бытия. Тексты переводов на сервер не загружаются, пока не решены права конкретного модуля.

## Срез 4. LLM

Кабинет ключа провайдера, чат, разбор изображений и локальный RAG. Запись песни идёт тем же push, что и правка человека.

## Оболочка

После устойчивого CLI: выбор папки VisioBible, выбор пространства, dry-run, кнопка синхронизации, предупреждение о запущенной программе, разрешение конфликта. Автозапуск и фоновый режим отдельно. Надпись «синхронизировано» появляется только когда локальный файл и сервер сошлись, а конфликты показаны.
